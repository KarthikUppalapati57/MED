MarginEdge Products Module

This workflow describes how MarginEdge publicly documents Products: products are generic items used for reporting, inventory, recipes, and vendor-item matching. MarginEdge says invoice processing can match vendor items to existing products or create new products, and one product can have multiple vendor items associated with it.

Product Workflow Details

  1. Processed invoices are a primary product source: MarginEdge documents that each food or beverage vendor item is matched to an existing product or a new product is created if no appropriate product exists.
  2. Manual product creation is available to Restaurant Admin or MarginEdge Admin roles from Products > View All Products > Add Product.
  3. When adding a product, users enter/select product name, category, inventory/report flags, count-by unit, starting price, and allergens where applicable.
  4. Product review columns include name, category, accounting code, item count, inventory flag, tax exempt flag, report by unit, and latest price.
  5. Latest price is location-specific when product databases are shared; invoice-associated vendor items update the product price automatically.
  6. Vendor items can be reassigned from a product to an existing or new product, with conversion between vendor packaging and product count-by unit.

This map follows the one-page reference PDF style, but represents MarginEdge's documented public inventory workflow rather than this repository's internal implementation.

Inventory Workflow Details

  1. Users first decide which products and/or recipes to inventory and how to count them.
  2. Count sheets are reusable templates. Inventory counts are the dated results of counting those sheets.
  3. Multiple count sheets can exist for one restaurant, and count sheets from the same date roll into one inventory total.
  4. Products can be organized by Auto by Category or Sheet to Shelf. Sheet to Shelf supports custom sections matching physical storage areas.
  5. Inventory count entry uses a selected count sheet and inventory date; users enter counts directly or add to existing counts.
  6. Inventories remain Saved until closed. MarginEdge says all inventories need to be closed to see usage report details.
  7. Accurate theoretical usage reporting generally requires two closed inventories plus PMIX mapping and POS connection.
